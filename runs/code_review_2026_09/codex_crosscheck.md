### Fable F6, MLL half (S3 claimed) — posterior draws receive another likelihood weighting — **CONFIRMED-NARROWED (recommended S3)**

What I checked: `bistar_gp/induced_prior.py:170-199,224-239` requires `log_mlls` and uses their normalized exponentials to average G. The values supplied by `compute_log_marginal_likelihoods` are log likelihoods, not a proposal-density correction (`bistar_gp/aggregation_v3.py:303-309,347-363`). `experiments/bistar_induced_prior.py:129-166` loads cached draws, extracts predictives, computes those likelihoods, and passes them through. Its documented cache producer calls `fit_hmc` and saves the samples (`experiments/bms_star_toy.py:68-92`); current `fit_hmc` routes to corrected posterior NUTS (`bistar_gp/fit.py:397-414`). The repository itself states that uniform mixture weights are correct for posterior draws (`aggregation_v3.py:60-63`).

Failure scenario or why none exists: for posterior draws distributed as `p(η|D)`, multiplying their contributions by `p(D|η)` changes the averaging distribution to one proportional to `p(η)p(D|η)^2`. The executable two-state example uses equal prior masses, likelihood ratio `1:9`, and a posterior represented by one mean-0 row and nine mean-2 rows, all with unit variance. For candidate means 0 and 2, proper posterior averaging gives G=`[1.8,0.2]`; the implementation with actual log likelihoods gives `[1.975609756,0.024390244]`. The resulting parameter weights change from `[0.167981615,0.832018385]` to `[0.124420444,0.875579556]` (`probe_f8_f6.json`, F6 block).

Narrowing: the demo loads a cache rather than calling `fit_hmc` directly, and its default HMC cache files are absent here; it skips missing caches (`bistar_induced_prior.py:130-133`). The failure becomes reachable when valid posterior caches are supplied. Moreover, actual MLL weighting is not unavoidable: the probe passed zero `log_mlls` and recovered uniform posterior averaging. Thus the required argument and the legacy caller are the problem, not an inability to express uniform weights. The function explicitly advertises its MLL-weighted strategy (`induced_prior.py:185-189`), but that strategy is not ordinary averaging under the supplied posterior. Caller searches found only the legacy `bistar_induced_prior*.py` scripts and no target-specific test or manuscript artifact using this function. Retain S3 for this unexercised posterior-reweighting path; the negative-metric sentinel half was not re-reviewed.
