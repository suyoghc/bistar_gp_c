[S3] [docs/paper-sie-jmp/05-case-C-nested-constraints.md, ¶2 ("Both candidates call the same bounded MLE routine, use the same starts...")] — The claim that the two candidates "use the same starts" is not what the code does. In `fit_nested_pair` (experiments/haaf_nested_constraint.py), the constrained `fit_all` receives `extra_starts=[v.copy() for v in free_vectors]`, i.e., the free fit's solutions as additional starts, while the free fit receives no extra starts; likewise `observed_pair` passes `extra_starts=[free_best]` only to the constrained fit. Symmetry is restored only afterward, at the candidate-selection stage (each side's candidate pool includes the other's fitted vectors). Why it matters: the prose describes the optimizer protocol, and the protocol is asymmetric at the start level even though the final selection pools are shared. Concrete fix: rephrase to e.g. "Both candidates call the same bounded MLE routine from the same base multistart set, and each side's solution set is included in the other side's candidate pool before selection, so both select from a common pool; they share every bound except the lower bound on b."
